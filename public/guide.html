Step 1
📋
Bookings Come In
Staff uploads a PDF invoice. The system extracts client name, travel date, route, passenger count, vehicle type, and more — automatically.
Step 2
🚐
Vans Get Assigned
The scheduling engine matches each booking to the best available van — considering date, location, passenger capacity, and whether the van can cross borders (Singapore / Thailand).
Step 3

If two bookings compete for the same van, the higher-priority trip wins. The lower one either gets moved to another van or is flagged for outsourcing.

The Scheduling Brain

Two engines, one goal

The system has two scheduling engines. They both assign vans — but in very different ways. Think of them as a rulebook vs a smart advisor.

Engine 1
⚙️
Rules Engine
Fast, deterministic, zero cost. Follows a strict 7-step process every time. Same input always produces the same output. Great for predictable schedules.

Used by: Recheck button, Quick Upload, per-row reassign
Engine 2
🤖
AI Scheduler (Gemini 2.5 Pro)
Smarter decisions for complex conflicts. Understands context, can reason about edge cases. Sends bookings to Gemini in batches of 50. Falls back to the Rules Engine if the API fails.

Used by: Preview → Insert flow, AI chat

The 7-Step Rules Engine Process

1
Reset auto-managed bookings — Clears all van assignments that were set automatically (not manually by staff), so we start fresh.
2
Run priority-based assignment — Goes through all bookings in priority order. Day trips first, then standard trips, then one-way rides. Higher priority can bump lower ones.
3
Enforce invoice continuity — Same invoice number = same van, always. If a customer has a multi-day trip or return leg, they get the same driver throughout.
4
Fix same-day multi-vehicle conflicts — If one invoice needs 3 vans on the same day, makes sure they're all different vehicles.
5
Eliminate double-bookings — Finds any van assigned to two trips at the same time. Keeps the higher-priority one; displaces or outsources the other.
6
Mark remaining as outsourced — Any booking still without a van gets flagged as "needs outsourcing". Staff will be alerted to fill in the outsource company.
7
Final validation — One last sweep to catch any remaining double-bookings, unnecessary outsources, or capability rule violations.

How "Bumping" Works
When a high-priority trip needs a van that's already taken by a lower-priority booking, the system bumps the lower one out. The bumped booking then gets a second pass to find another free van. If it still can't find one — it gets outsourced. The bumped booking cannot bump anyone else on its second pass.
Protection Rules

What the system will never touch

Some bookings are locked and immune to any automated changes. The system respects these absolutely — no exceptions.

🔒
Manual Lock
Staff clicked "lock" on a booking. It will never be automatically reassigned, bumped, or touched by any engine — ever.
🏢
Confirmed Outsource
Marked as outsourced AND has a company name filled in. That's a deliberate human decision — the system leaves it alone.
🚗
Car Trips
Vehicle category "Car" is always outsourced, always. Your fleet doesn't have cars — so the system never tries to assign one.
👑
Alphard Trips
Only Toyota Alphard vans can be assigned. Regular vans and Alphards never mix — even if a regular van is free.
💡
Outsource Reason
When the system outsources a booking automatically, it now records why — so you can see at a glance whether it was bumped by a priority trip, or just because no van was free. The reason shows in orange below the company name field.
